# What has actually been checked

This is the source/build handoff. **No device IPA has been compiled or signed in this Ubuntu session, and the app has not been run on a physical iPhone or in LiveContainer.** Those checks need the supplied macOS workflow and your device.

## Passed here

- **21 behavior tests:** strict and parallel prerequisites, paused dependencies, complete/topic totals, sensible lesson ranking, known-name acquisition kept separate from transfer, immutable note updates, honest unknown/zero observations, count/date validation, distress guidance, trigger filtering, backups, invalid/oversized inputs, and storage allowance.
- **17 interface scenarios in each of Chromium and WebKit:** single-click tab navigation, exact step and prerequisite links, saved skills and searches, profiles, unsaved forms, journal validation/edit/delete, charts, trigger plans, backup export/import/cancellation, and all lesson/topic/source routes.
- The route sweep covers **230 lesson pages, 14 topic pages and 67 source pages** in each engine. External references are checked as links, not loaded into the offline interface.
- Layouts at **320, 390, 430 and 768 pixels** have no document-level horizontal overflow on the tested screens. Light/dark themes and the larger-text setting were exercised.
- Automated WCAG A/AA checks found **no violations on the tested six main/form/research screens and progress dialog**. This is not a full accessibility certification or a VoiceOver test.
- **8 native-bridge contract scenarios per engine:** the actual bundled `file://` page, save messages/acknowledgements, cold-start supplied data, reading swipes, failed-save warnings and retry, older acknowledgements, export/import, and protecting/recovering corrupt saved records. The JavaScript bridge endpoint was simulated here; these tests do not execute Swift or prove on-device filesystem behavior.
- No external network request occurred while the bundled screens were exercised.
- Source/teaching IDs, acyclic prerequisites, reference IDs, all trigger-program links, and matching JSON/JavaScript bundles pass structural checks. Every teaching step includes an actual procedure, a criterion and easier/stop advice.
- The source ZIP was extracted independently, its core checks rerun, and its curriculum regenerated byte-for-byte. All local handoff-document links resolve.
- Native plist, privacy manifest, icon references and shell syntax were checked. The GitHub workflow also passes actionlint 1.7.12 (its optional shellcheck/pyflakes integrations were not used). Original vector icons and clean interface screenshots were rendered.
- An HTTP reference audit found **66 reachable URLs, one access restriction, and no 404/410 responses**. This is a reachability check, not proof of full-text access or a claim every paper was read completely.

Raw reports are in [validation](validation). Chromium and WebKit are desktop browser engines with phone-size/touch emulation; they are useful interface evidence, not substitutes for iOS device testing.

## Configured but still pending

The GitHub workflow first repeats the interface checks on disposable Linux runners. Its Mac job then:

1. Compiles an unsigned arm64 iOS device application using Xcode’s SDK.
2. Packages `Payload/GoodGround.app` as `GoodGround-unsigned.ipa`.
3. Separately compiles a simulator app.
4. Launches that app in an iPhone simulator and checks local-file loading, prerequisite navigation, native save acknowledgement, backup validation and an actual progress file on disk.
5. Offers the IPA artifact only after those checks pass, and saves simulator diagnostics separately.

The device build contains no simulator test history. The smoke test changes only the simulator’s private data container after the device bundle has already been packaged.

On your iPhone, the remaining checks are signing/installing through the existing SideStore or LiveContainer setup, launch and safe-area layout, close/reopen persistence, Files export/import, opening an original reference in your browser, and any LiveContainer-specific compatibility. INSTALL.md gives a short first-use check.
